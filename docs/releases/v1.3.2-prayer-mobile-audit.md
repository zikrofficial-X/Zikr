# ZIKR 1.3.2 — Prayer and mobile permission audit

Date: 2026-09-06

## Changes

- Location permission state `prompt` is no longer treated as denial; the browser/native prompt can complete normally.
- Prayer location requests now validate latitude/longitude before using them.
- Location requests use high accuracy with a bounded 15-second timeout and a five-minute cache window.
- Denied, timed-out, unavailable, or malformed location results show an Arabic recovery message and keep city search available instead of silently replacing the user location with Cairo.
- Native notification channels are initialized without requesting permissions at app startup.
- Push notification permission is no longer requested during app startup. It is requested only after the user explicitly enables server-backed reminders.

## Permission inventory

- Location: requested only by the prayer location action; no background location permission is declared.
- Local notifications: used for scheduled prayer reminders; prompt is deferred until the user enables reminders.
- Push notifications: startup prompt removed; explicit opt-in flow remains available.
- Camera and microphone: declared for the existing profile/media and memorization features.
- Exact alarms: exposed through the explicit Android reminder setting, not requested at startup.

## Device testing limitation

Browser and static/native bridge checks do not replace testing on a physical Android/iOS device. Before store publication, test location denial/approximate location, notification denial, timezone changes, reboot/reschedule behavior, exact alarms, audio focus, and background delivery on supported OS versions.

## Publishing

This document records the source-level audit and verification. A signed store artifact and GitHub Release must be created from a CI or local release runner with Java, Android SDK, signing keystore, and store credentials available; those artifacts cannot be generated in this Linux VM without JDK tooling.
