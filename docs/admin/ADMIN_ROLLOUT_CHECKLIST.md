# مراحل تطوير لوحة إدارة ذِكر — سجل التنفيذ

**تاريخ المراجعة:** 21 أكتوبر 2026  
**الفرع:** `feat/admin-mobile-navigation-governance-20261021`

هذا السجل يفرق بين ما هو موجود بالفعل في الكود وما تم تغييره في هذه المرحلة، بدل إعادة بناء وحدات موجودة أو اعتبار خطة مكتوبة تنفيذًا.

| المرحلة | النتيجة المستهدفة | حالة الفرع |
|---|---|---|
| 0 — الجرد وخريطة الملكية | توثيق مسارات الإدارة والصلاحيات وحدود البيانات | تم: أضيف جرد قابل للفحص آليًا إلى `docs/admin/ADMIN_CONSOLE_GOVERNANCE.md`. |
| 1 — التنقل والمسارات | مجموعات واضحة، مسارات قياسية، تحويلات للمسارات القديمة، بلا روابط مكررة | قائم في الكود؛ `admin:architecture:check` يراجع المجموعات والمسارات والتحويلات والتكرار. |
| 2 — واجهة موحدة ومتجاوبة | RTL، تحديد الصفحة الحالية، تنقل سطح المكتب والهاتف | تم توسيع التنقل المحمول ببحث في كل صفحات الإدارة، بما في ذلك تجميع النتائج وإظهار حالة عدم وجود نتائج. |
| 3 — الصلاحيات والأمان | حراسة خادمية لكل صفحة، صلاحيات للأدوار، MFA للأعمال الحساسة، سجل تدقيق | قائم في الكود؛ تمت إضافة فحص حوكمة يعاود التأكد من هذه الثوابت. تفعيل حماية كلمات المرور المسربة في Supabase Auth متابعة خارج مستودع الكود. |
| 4 — المحتوى والمعرفة | فصل إدارة المحتوى والمكتبة والمصادر والتحرير والمعلومات الإسلامية | المسارات والخدمات وعقود الإدارة موجودة؛ يظل كل مسار خاضعًا لفحوص الصفحات والبناء. |
| 5 — الفيديو والوسائط والنشر | مصنع الفيديو والطوابير وQA والمصادر والنشر الاجتماعي | المسارات وفحوص الفيديو والنشر موجودة؛ لا تعاد جدولة مهام الإنتاج كجزء من تعديل التنقل. |
| 6 — الأطفال والصوت | محتوى الأطفال والألعاب والمستويات والأصول والتحليلات والصوت | المسارات وفحوص الألعاب والصوت موجودة؛ لا تغيير في بيانات الأطفال أو مخططها ضمن هذا التحديث. |
| 7 — الإعدادات وSEO والإصدار | إعدادات، أمن، SEO، صحة النظام، إصدار Android | المسارات وأدوات التحقق موجودة؛ تعديلات الإنتاج تتطلب التحقق من بيئة النشر الفعلية. |
| 8 — الجودة والنشر | اختبارات محلية، فحوص الأنواع والـlint والبناء، ثم Preview وProduction smoke | فحوص Node المستقلة في النسخة المتاحة اجتازت فحوص الإدارة والأمن والمسارات. فحص replay للمهاجرات لم يعمل في بيئة الفحص المحلية لغياب `@electric-sql/pglite`، كما لم يتوفر `pnpm` بسبب تعذر الوصول إلى registry. يلزم انتظار نتيجة CI على الفرع قبل إعلان اكتمال البناء. |

## بوابات قبول الدمج

- [ ] `pnpm admin:architecture:check` ينجح.
- [ ] `pnpm admin:pages:check` ينجح.
- [ ] `pnpm admin:governance:check` ينجح.
- [ ] `pnpm check` و`pnpm lint` ينجحان.
- [ ] `pnpm build` ينجح.
- [ ] فحوص Supabase migrations وRLS لا تكشف تراجعًا.
- [ ] Preview من Vercel يعمل وتُختبر عليه صفحات الإدارة على شاشة هاتف وسطح مكتب.
- [ ] لا تُدمج تغييرات الواجهة إلى `main` قبل اجتياز الفحوص؛ وبعد الدمج يُتحقق من عنوان الإنتاج وحالة النشر وسلامة مسارات الإدارة.


## ملحق تنفيذي — معالجة RBAC/RLS الحرجة (30 أكتوبر 2026)

| العمل | حالة الكود |
|---|---|
| توحيد حل الدور من تعيينات RBAC بدل الاعتماد المنفرد على `profiles.role` | أضيفت migration |
| منع الأدوار المفوضة من وراثة صلاحيات المدير العام في RLS | أضيفت دالة الدور وسياسة المدير العام |
| حصر الكتابة المباشرة على جدول تعيين الأدوار في `super_admin`، وقصر منح الأدوار الكاملة وتعديل حساباتها عليه؛ الأدوار المفوضة عبر Server Action محمي | أضيفت قيود RLS وحارس Server Action |
| مواءمة سجل التدقيق مع `audit.read` | أضيفت سياسة أدوار محددة |
| مواءمة تنبيهات الطوابير مع `notifications.manage` | أضيفت سياسة أدوار محددة |
| حصر طابور النشر الاجتماعي في الإدارة و`social_manager` | أضيفت سياسة محددة |
| منع رجوع التعارض عبر اختبار مستقل | أضيف `pnpm admin:rbac:check` إلى بوابة `verify` و`verify:pr` |

**بوابة الإغلاق:** لا تعد المعالجة مكتملة إنتاجيًا إلا بعد تطبيق migration على مشروع Supabase الصحيح، وفحص السياسات الفعلية، ونجاح CI وVercel Preview ثم Production smoke. لا تُحذف بيانات الأدوار ولا تُعدّل سجلات المستخدمين أثناء هذه المعالجة.
