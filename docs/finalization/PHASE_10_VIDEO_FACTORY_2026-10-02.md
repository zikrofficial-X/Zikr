### Code findings and fixes

#### 1. Provider exceptions could abort fallback

Previously, a provider's `generate()` or `isAvailable()` exception could bubble out of the router and prevent later providers from being tried.

Fixed in `src/features/videos/providers/provider-router.ts`:

- Availability exceptions are caught and treated as provider-unavailable.
- Generation exceptions are caught and the router continues to the next candidate.
- The template provider is not retried twice in one router pass if it was already attempted.

#### 2. Runtime identity fork

`template-video-automation.ts` and `video-sources.ts` had their own hardcoded production origin.

Fixed by using the canonical `getServerEnv().NEXT_PUBLIC_SITE_URL` value.

The generated Dua source URL in the autonomous worker now uses the same canonical site configuration.

#### 3. Source lock and render QA preserved

The existing worker already enforces the critical integrity sequence:

`selected source → exact source-text match → optional source audio → provider/render → media probe → audible-audio check → storage`

It rejects:

- missing/unpublished source records,
- source-text drift,
- missing video/audio streams,
- wrong resolution,
- non-H.264 video,
- non-AAC audio,
- too-low video bitrate,
- silent/near-silent audio.

No source text is regenerated by the AI visual planner.
