# تقرير تطوير لوحة الإدارة والوسائط — 22 أغسطس 2026

## النطاق
تم تطوير تدفق إدارة الوسائط في لوحة الإدارة، مع الحفاظ على صلاحيات admin، وعدم نقل أسرار Cloudinary إلى المتصفح، وعدم تغيير مخطط Supabase.

## ما تم تنفيذه
أُضيف مسار خادمي `POST /api/admin/cloudinary/image` لا يقبل الطلب إلا بعد `requireAdminApi`. يتحقق المسار من نوع الملف وحجمه، ويقصر مجلدات الرفع على مجلدات ZIKR المعروفة، ثم يرفع الصورة عبر Cloudinary من الخادم فقط ويعيد `secureUrl` و`publicId`.

أُضيف مكوّن عربي قابل لإعادة الاستخدام يعرض اختيار الملف، حالة الرفع، المعاينة، رسائل الخطأ، والرابط المخفي الذي تحفظه Server Actions. استُخدم المكوّن في إعدادات الصفحة الرئيسية، القصص، المقالات، الفيديوهات، المسابقات، وقسم الأطفال. وبذلك لم تعد النماذج الأساسية تتطلب لصق روابط الصور يدويًا.

تدفق الفيديو الحالي يحافظ على رفع الفيديو إلى Supabase Storage، بينما أصبحت الصورة المصغرة ترفع إلى Cloudinary. كما بقيت ضوابط التوليد والنشر الاجتماعي والمراجعة الحالية دون فتح نشر ديني مولّد تلقائيًا من دون نص يراجعه المسؤول.

## الأدلة
نجح `pnpm verify`: عدد الاختبارات 60، الفاشل 0، وتجميع TypeScript وNext.js production build ناجحان. اختبار أمني محلي لمسار رفع Cloudinary بلا جلسة إدارية أعاد `401 Unauthorized`. فحوص CircleCI للـPR 209 والـPR 210 نجحت.

## GitHub وVercel
تم دمج التطوير الأساسي في PR 209. أُنشئ PR 210 لتوحيد قسم الأطفال، لكن لا يمكن دمجه حاليًا لأن فحص Vercel الخاص بمشروع `v0-project` يعيد: `Deployment rate limited — retry in 24 hours`. هذا عائق حسابي في Vercel وليس خطأ compile أو TypeScript. فحص `Vercel – zikr` وCircleCI ناجحان، بينما يظل PR 210 مفتوحًا حتى انتهاء rate limit.

## متطلبات الإنتاج
يجب ضبط المتغيرات السرية التالية في Vercel لكل بيئة تحتاج الرفع: `CLOUDINARY_CLOUD_NAME` و`CLOUDINARY_API_KEY` و`CLOUDINARY_API_SECRET`. لا ينبغي وضعها في ملفات العميل أو المستودع. بعد انتهاء rate limit يجب إعادة فحص PR 210 ثم دمجه بالطريقة المحمية.
